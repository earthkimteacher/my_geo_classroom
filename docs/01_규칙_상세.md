## 교사와 일하는 방식
- **말투:** 모든 답변과 슬라이드는 한국어. 존댓말로, 쉬운 말로 씁니다. 코드 설명보다 "수업 화면에서 어떻게 보이고 무엇이 달라지는지"를 중심으로 보고합니다.
- **큰 작업은 구성안 먼저:** 새 수업이나 한 장을 크게 다시 짜는 일은, 먼저 장별(또는 클릭 단계별) 구성안을 표로 보여 주고 확인받은 뒤 만듭니다. 구성안에는 화면 배치, 클릭 단계마다 무엇이 나타나는지, 그림·애니메이션 아이디어, 쓸 색을 적습니다.
  - 2026-10-26부터: 교사의 PPT로 만드는 수업은 구성안 없이 바로 만들고(내용은 PPT, 배치는 기존 스타일) 미리보기로 확인받습니다. 구성안은 Claude가 새로 설계하는 부분(그림을 모션 그래픽으로 바꾸기 등)에만 씁니다.
  - **2026-11-02 교사 결정 — PPT가 없을 때:** PPT를 미리 줄 때만 PPT에 맞춰 만듭니다. PPT 없이 교과서·지도서·참고서만 주면, Claude가 그 자료를 바탕으로 **조석 수업처럼 장마다 다른 모션 그래픽·시뮬레이션·인터랙티브로 다채롭게 구성해 초안을 먼저 만들고**(조석 때처럼 **장별 구성안을 먼저 표로 보여 주고 교사 확인을 받은 뒤** 만듦 — 2026-11-02 교사 확인), 교사가 지시하는 대로 고칩니다. 교사 지적: III.03 첫 초안이 PPT 규칙처럼 '그림 상자 + 카드' 틀을 모든 장에 되풀이해 정형화됨 → `III.03stability_old.html`로 보관하고 처음부터 다시 만듦(이 초안은 2026-11-03 교사 요청으로 삭제).
- **작은 수정은 바로:** 색 바꾸기, 글자 잘림, 버튼 동작 같은 것은 바로 고치고 미리보기로 확인한 뒤 보고합니다.
- **커밋·push 전에 교사가 내용을 먼저 확인:** 고치거나 새로 만든 것이 있으면, 커밋하기 전에 교사가 직접 볼 수 있게 보여 줍니다(2026-10-21 교사 요청). 문서(README·CLAUDE.md 등)는 바뀐 부분의 실제 내용을 대화에 그대로 보여 주고, 슬라이드는 브라우저 미리보기 화면을 띄워 바뀐 장을 보여 줍니다. 교사가 확인하고 승인한 뒤에만 커밋합니다.
- **커밋·push는 매번 물어본 뒤에만:** 내용 확인이 끝나면 "커밋하고 push할까요?"라고 묻습니다(push = 공개 사이트 반영). 이전에 승인했어도 다음 변경은 다시 묻습니다. 교사는 보통 "커밋하고 GitHub에 push까지 해줘"라고 답합니다.
  - **예외 — 학생용 PDF(2026-10-22 교사 결정):** 교사가 "PDF 만들어 줘"라고 하면 PDF를 만들어 `과목폴더/PDF/`에 저장하고, `index.html`·`README.md`에 내려받기 링크를 넣은 뒤 **묻지 않고 바로 커밋·push**합니다. 다만 슬라이드 자체에 아직 커밋하지 않은 수정이 있으면 그 수정은 따로 확인받은 뒤 함께 올립니다(PDF는 확인받은 슬라이드로만 만듦).
- **작업 시작 전에 `git pull`:** 새 대화를 시작하면 파일을 고치기 전에 `git status`로 깨끗한지 확인하고 `git pull`로 GitHub 최신본을 받습니다. (저장소가 여러 PC에 동기화되는 폴더에 있고, 교사가 GitHub 웹에서 직접 고치기도 하기 때문) 고치지 않은 변경이 이미 있거나 pull이 충돌하면 손대지 말고 교사에게 알립니다.
- **push 전에 `git fetch`:** 교사가 GitHub 웹에서 직접 파일을 옮기거나 지우는 일이 있습니다(작성자 StarFinder). 원격에 새 커밋이 있으면 무엇인지 확인하고, 내 변경과 겹치지 않으면 `rebase` 후 push하고 그 사실을 알립니다. 겹치면 교사에게 묻습니다. 원격 변경 때문에 이 문서 내용(경로 등)이 틀려지면 함께 고칩니다.
- **범위 밖 문제는 알리기만:** 작업 중 발견한 다른 문제는 마음대로 고치지 말고 알려 줍니다.
- **확인·결정을 여쭐 때는 전후 비교 스크린샷으로**(2026-11-11 교사 요청 '고칠 점을 검사받고 싶으면 비교 사진이나 스크린샷을 제공하도록'): 글로만 '~할까요?'라고 묻지 않습니다(글만 나열했더니 '뭘 말하는지 모르겠어. 그림을 직접 보여줘'라고 함).
  - 여쭐 항목마다 **지금 화면**과 **바꾼 화면**을 실제로 만들어 찍고, 한 그림에 나란히 놓아 보냅니다(왼쪽 '지금', 오른쪽 '바꾼 화면', 위에 몇 번 항목·몇 장인지 제목). 차이가 작은 곳은 그 부분만 크게 잘라 넣고, 근거가 되는 교과서 그림·문장이 있으면 아래에 '참고'로 붙입니다.
  - 그림과 함께 항목마다 두세 줄: 지금은 어떤지, 바꾸면 어떻게 되는지, 추천과 그 까닭. 교사는 번호로 답합니다('1번은 추천대로', '5번은 바꾼 화면').
  - 바꾼 화면은 수업 파일의 평소 화면을 건드리지 않게 임시로 만듭니다(2026-11-11에는 주소에 `?alt=글자`를 붙일 때만 켜지는 임시 코드를 넣어 찍고, 결정 뒤 지움). 비교 그림은 저장소 밖 `C:\2026 진광고\Claude\`에 `비교N_이름.png`로 저장하고 커밋하지 않습니다.
  - 새 수업을 처음 보여 줄 때도 장별 마지막 단계를 모은 그림(한눈에 보기)을 함께 보냅니다.
- **`karpathy-guidelines` 스킬은 대화를 시작할 때 불러옵니다**(2026-10-22 교사 요청, 2026-10-23 '코드 고치기 전'에서 '대화 시작할 때'로 바꿈): 새 대화에서 작업 환경을 불러올 때(`git pull`과 함께) 이 스킬을 처음부터 불러 둡니다. 그리고 요청한 범위만 작게 고치고, 가정은 드러내 말하고, 확인할 수 있는 완료 기준(이 문서의 '검증 방법')으로 끝냅니다. 이 문서의 규칙과 다르면 이 문서를 우선합니다.
- **교사가 내용을 질문하면:** 먼저 개념을 설명하고, 학생도 같은 데서 막힐 수 있으면 슬라이드 개선안을 제안합니다(2026-10-26부터는 PPT를 고칠 내용으로 제안하고, 교사가 정한 뒤에 반영).
- **작업 메모는 필요할 때만**(2026-11-03 교사): `작업메모/` 파일은 작업 도중 PC를 옮기는 등 다음 대화가 이어받아야 할 때만 만듭니다. 늘 만들 필요는 없습니다. 수업을 만들며 정한 것·바꾼 과정·교사 결정은 이 문서의 '만든 수업 기록'에 적어, 메모가 없어도 이 문서만으로 이어서 일할 수 있게 합니다. 작업 도중에 PC를 옮길 때는 메모도 커밋·push해서 옮깁니다(아래 'PC를 옮길 때는 GitHub로만').
- **학생 피드백(2026-10-23, 교사 전달):** ① AI 말투로 설명한 부분이 이해되지 않는 경우가 많다 ② 글씨가 너무 작고 세세하다 ③ 그림이나 모양이 오개념을 유발하는 경우가 많다. 이때 Claude가 낸 디자인 개정안(본문 40px 이상, 장당 120자 이하, 화살표·괄호·나열로 압축한 문장을 완전한 문장으로 등)은 조석에 시험 적용했다가 교사가 '전면 취소, 나중에 다시 이야기해 줄게'라고 함. 그 뒤 2026-10-26 '수업 자료 제작의 기본 규칙'(내용은 교사 PPT), 카드 글자 키움(36px), 교과서 용어만 쓰기, 과장 점검으로 이어짐. 화면 문장을 쓸 때 이 세 가지를 늘 떠올립니다.

## 수업 자료 제작의 기본 규칙 (2026-10-26 교사 결정 — 이 문서의 다른 규칙보다 우선)
**적용 범위(2026-11-02 교사 결정): 이 절은 교사가 PPT를 미리 줄 때만 따릅니다.** PPT 없이 교과서·지도서·참고서만 받으면 이 절 대신 아래 '교사의 수업 자료 스타일'(도입 질문·흥미 유발·오개념 짚기·확인 문제 장, 용어를 그림과 잇기, 계산으로 그리기)과 '슬라이드 설계 원칙'(장마다 알맞은 다른 모션 기법)을 처음부터 그대로 적용해 Claude가 구성합니다(위 '교사와 일하는 방식'의 2026-11-02 결정).

수업의 **내용**(다루는 순서, 문장, 용어 설명, 그림)은 교사가 만든 PPT와 교사가 준 PDF를 따르고, **화면의 배치와 디자인**(표지, 키워드 장, 장 안의 배치, 빈칸, 모션)은 Claude가 기존 수업 스타일대로 만듭니다. 교사가 표시한 인터랙티브 자료도 Claude가 맡습니다(2026-10-26 교사 보충: '내 PPT의 레이아웃에 너무 의존할 필요는 없다. 문장·내용·그림을 PPT에 기반하라는 뜻이고, 표지·장 배치·중요 단어 빈칸 등은 기존 스타일대로'). 이 규칙 이전에 Claude가 구성안을 짜고 그림을 직접 계산해 그려 만든 세 수업(조석, 과탐 I.06, 통합과학2 II.1.3)은 그대로 둡니다.

1. **디자인과 모션은 쓴다:** 미려한 디자인과 알맞은 모션 그래픽(아래 '슬라이드 설계 원칙'과 기법표)을 활용합니다. 단, 내용(문장·용어 설명·그림)을 바꾸지 않는 범위에서 씁니다.
2. **내용은 교사의 PPT 그대로, 배치와 디자인은 기존 스타일로:** 수업 구성과 용어 설명은 Claude가 임의로 정하지 않고 교사가 미리 만들어 준 PPT를 따릅니다. 화면을 어떻게 꾸미고 배치할지는 PPT의 레이아웃에 얽매이지 않고 기존 수업(조석 등)의 스타일로 만듭니다.
   - **PPT를 따를 것:** 다루는 내용과 순서, 화면의 문장과 용어 설명(고쳐 쓰지 않고 그대로 — 맞춤법이나 과학적 내용이 걸리면 고치지 말고 알림), 그림(아래 3). PPT에 없는 개념·설명 문장은 더하지 않습니다(필요해 보이면 제안만).
   - **기존 스타일로 할 것**(자세한 틀은 아래 '새 수업 슬라이드 만드는 순서 → 2026-10-26부터 — 교사의 PPT로 만들 때'): 움직이는 장면이 있는 표지, 오늘의 키워드 장(오른쪽 위 키워드 표시 `window.KW` 포함), 머리(`.hd`: 키워드 번호 + 제목), 학습지 카드(`.ws-card`)·흐름 칩 같은 부품, **문장 속 중요 단어 빈칸**(`.bk`, 한 단계에 하나씩), 장 안의 배치, 색 약속, 클릭 단계. 키워드 이름·칩 글자·그림 이름표처럼 짧은 이름은 PPT의 낱말에서 가져옵니다.
   - **정렬과 간격(교사가 매우 중요하게 여김, 2026-10-26):** 모든 장이 같은 격자를 씁니다 — 좌우 여백 120px(내용 x 120~1800), 머리 아래 내용 시작 y 250, 단·개체 사이 40px, 내용 아래 끝 y 990 이내. 나란한 개체는 위·아래 끝(높이)을 맞추고, 가장자리는 격자 선에 맞추며, 같은 종류의 간격은 같게 합니다. 만든 뒤 각 장의 개체 위치를 재서(검증 방법 5) 어긋난 곳을 고칩니다.
   - **클릭 단계는 Claude가 알맞게 판단해 넣습니다**(2026-10-26 교사 결정): PPT에 애니메이션이 있으면 그 순서를 참고하고, 없으면 설명하는 순서에 맞춰 나눕니다(예: 빈칸은 하나씩, 그림 → 설명). 어떻게 나눴는지 미리보기와 함께 알립니다.
   - 발표자 노트는 PPT의 슬라이드 노트를 그대로 옮깁니다. 노트가 없으면 비워 둡니다(Claude가 설명을 지어 넣지 않음. 인터랙티브 장의 조작 방법만 예외).
3. **그림과 그래프는 교사가 준 PDF의 그림을 그대로 씁니다:** PPT에서 그림 자리에 해당하는 그림을 PDF에서 잘라 넣습니다.
   - **3-1. 저작권:** 교사가 모두 해결해 두었으므로 그대로 써도 됩니다(2026-10-26 교사 확인).
   - 그림만 깔끔하게 잘라 넣습니다(주변 본문, 쪽 번호, 그림 번호 줄은 PPT에 있을 때만). 해상도는 높게 뽑고(PDF에서 3~4배 확대해 그림으로 저장), 그림 속 글자·숫자·색은 고치지 않습니다. 그림이 과학적으로 걸리면 알리기만 합니다. 사진은 격자에 맞추려고 가장자리를 조금 잘라 넣어도 되지만(`object-fit:cover`), 도표·모식도·글자가 든 그림은 자르지 않습니다.

- **교과서 '스스로 확인하기' 장**(2026-10-29 교사 요청): 교과서(교사용)의 문제와 예시 답안을 그대로 쓰고, 문제를 모두 먼저 보여 준 뒤 클릭할 때마다 예시 답안이 하나씩 나오게 합니다(`.sc-list`·`.sc-q`·`.sc-a`). 한 장에 넘치면 두 장으로 나눕니다(III.03: 1·2 / 3). 학생용 인쇄(`?ans=0`)에서는 예시 답안 상자(`.sc-a`)를 비워 둡니다(2026-11-03, 엔진 규칙 — 그 전에는 빠져 있어 학생용 화면에도 답안이 보였음).

- **강조는 지금 설명하는 것만 정확히**(2026-10-23 교사 지적): 표의 한 줄을 설명하며 그림을 강조할 때, 그 줄에 해당하는 화살표·숫자만 진하게 합니다. 여러 화살표를 묶음으로 강조하면 관계없는 것(예: 대기 줄인데 지표의 47, 우주로 가는 12)까지 켜지므로, 그림 요소마다 이름을 붙여(`data-a`) 하나씩 고릅니다.
- **학습지와 맞추기:** 빈칸 번호(①②…)와 정답은 교사의 학습지와 같게 유지합니다. 장을 다시 짜도 빈칸 번호·내용은 바꾸지 않습니다. 지금 설명 중인 학습지 줄은 강조합니다(`.ws-row.cur` 같은 장 전용 스타일).

  - 항목 이름 모양(2026-10-29 교사 요청 '조금 키우고 약간만 진하게'): 글자 크기 `max(26px, .89em)` = 설명 글자의 약 0.9배(줄 글자 36px이면 32px, 27~29px이면 26px)로 설명보다 커지지 않게, 굵기 600, 밝은 면 색 `#5c5c61`(예전 `--t2` `#6e6e73`). 어두운 면은 `--t2` 그대로.

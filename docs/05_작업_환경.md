  - **2026-11-05 기록을 새로 써서 강제 push함**(커밋 작성자를 교사 계정으로 바꿈): 그 전에 clone한 다른 PC(맥북 `~/Documents/my_geo_classroom` 등)에서는 `git pull`이 '갈라짐(diverged)'으로 나옵니다. 그 PC에 push 안 한 커밋이나 고친 파일이 없는지(`git status`, `git log origin/main..HEAD`) 확인한 뒤 `git fetch` → `git reset --hard origin/main`으로 GitHub에 맞춥니다. 있으면 손대지 말고 교사에게 알립니다. 바꾸기 전 기록은 학교 PC의 `.git`(`refs/original/refs/heads/main`)에 남아 있음.
- **동기화 폴더 주의사항:**
  - 두 PC에서 동시에 이 저장소를 고치지 않습니다.
  - **`.git` 폴더는 NAS로 동기화되지 않습니다**(2026-11-03 확인: Synology Drive 동기화 규칙 `black_prefix = "."` — 이름이 '.'으로 시작하는 파일·폴더(`.git`, `.claude`, `.gitignore` 등)는 올라가지 않음). 그래서 PC마다 `.git`이 따로 있고 기록은 GitHub로만 맞춰집니다. NAS가 수업 파일만 먼저 바꿔 놓으면 `git status`에 '고친 파일'로 보일 수 있으니, `git fetch` 뒤 `git diff origin/main --stat`으로 GitHub 것과 같은지 보고, 같으면 pull로 맞추고 다르면 교사에게 알립니다.
  - 동기화 폴더에 `.git`이 없는 PC(다른 PC의 Claude가 'git 기록이 없다'고 한 경우)는 그 폴더를 GitHub에 연결합니다: `git init -b main` → `git remote add origin https://github.com/earthkimteacher/my_geo_classroom.git` → `git fetch` → `git reset origin/main`(파일은 그대로 두고 기록만 GitHub에 맞춤) → `git branch -u origin/main` → `git status`로 GitHub와 다른 파일 확인. `git status`에 이상한 오류가 나면 고치려 하지 말고 교사에게 알립니다. 모든 작업은 GitHub에 있으므로, 최악의 경우 새로 clone하면 됩니다.
  - 다른 PC에서 처음 작업할 때는 Git 설치(`winget install Git.Git`), `git config core.longpaths true` 확인, 첫 push 때 GitHub 로그인이 필요할 수 있습니다.
  - **동기화가 안 된 일(2026-11-03):** 학교 PC가 커널 패닉으로 멈춘 사이 다른 PC에서 작업·push했는데, 학교 PC 폴더에는 그 파일들이 들어오지 않았음(파일은 전날 작업 그대로, `.git`도 커밋 5개 뒤처짐). 그래서 시작할 때 `git fetch` 뒤 `git status -sb`로 뒤처졌는지 보고, 로컬에 커밋하지 않은 파일이 있으면 그 내용이 GitHub 쪽에 다 들어 있는지 확인한 뒤 로컬 본을 세션 임시 폴더에 백업하고 pull합니다(교사에게 알림).
- **맥에서 작업할 때**(2026-10-28 III.01~02를 맥에서 만듦): 저장소 `~/Documents/my_geo_classroom`(GitHub에서 clone), Node는 Homebrew로 설치(`node --check` 가능), 미리보기는 `python3 -m http.server 8080` → `http://localhost:8080/과목폴더/파일.html`, `.claude/launch.json`은 `.git/info/exclude`로 저장소에 올리지 않음.

## A4 학습지 만들기 (HTML, 2026-11-05 시험 중)
교사 요청으로 III.03 슬라이드를 바탕으로 A4 학습지를 시험 삼아 만듦. LaTeX(Tectonic)판도 만들어 봤으나 교사 결정으로 폐기하고 **HTML판만** 씀(LaTeX는 그림을 새로 그려야 하지만, HTML은 슬라이드 그림을 그대로 가져올 수 있음).
- **위치(저장소 밖, 커밋하지 않음)**: `C:\2026 진광고\Claude\학습지_시험\` — `도구/`(공용 스크립트: `svgfigs.js`·`printpdf.js`·`build.py`·`hc.js`·`serve.js`)와 수업마다 폴더(지금 `III.03stability/`). 수업 폴더에는 편집용 원본 `…_학습지_원본.html`, `build.py`, 그림 목록 `figs.json`, 슬라이드에서 꺼낸 그림 `fig/`(SVG), 글꼴 `fonts/`(KoPubWorld 돋움 woff2·약관), 완성본 `…_학습지.html`, PDF 두 개(`_학생용`·`_교사용`). 저장소 밖이라 GitHub로는 다른 PC에 넘어가지 않음(NAS 동기화에만 있음) — 정식으로 쓰기로 하면 저장소로 옮길지 교사와 정함.
- **교사가 정한 모양**
  - 빈칸은 **슬라이드의 원번호 빈칸만**(번호·정답 같게). 답 칸·고르기·'해 보기'·그림 속 이름표 가리기 같은 다른 빈칸은 만들지 않음. '직접 해 보기' 장은 넣지 않음. 탐구·헷갈리는 개념은 슬라이드 모습대로 옮기고, 스스로 확인하기는 쓰는 줄(교사용에는 예시 답안).
  - 장마다 본문(127.3 mm: 장 머리, 카드 줄, 슬라이드 그림) + 오른쪽 날개(44.7 mm, 연한 파랑 바탕: 용어 풀이·'왜?'·참고·그림 설명 — 슬라이드 노트와 교과서 날개에서, 완자 참고서처럼). 키워드 띠(①~⑤)로 장을 묶음.
  - 1쪽 위: 과목·대단원, 제목 + '학습지' 표시, 오른쪽에 '진광고등학교 교사 김덕영'과 학번·이름 칸(이 영역에는 날개 바탕 없음). 오늘의 키워드 줄은 넣지 않음. 2쪽부터 쪽 머리(과목·대단원 | 소단원)와 아래 가운데 쪽 번호.
  - 글꼴은 **KoPubWorld 돋움만**(그림 속 글자·식 포함, 인터넷 글꼴 없음). 돋움은 부등호 <, >를 꺾쇠(〈 〉) 모양으로 그려서 그 두 글자만 기본 고딕(`@font-face`의 `unicode-range`).
  - 그림은 슬라이드의 인쇄 모드 그림 그대로, 너비는 슬라이드 비율(무대 1 px ≈ 0.0756 mm: 반 폭 820 px → 62 mm, 전체 1680 px → 127 mm). 더 줄이면 그림 속 글자가 5 pt 아래로 작아짐.
  - 종이를 넓게(교사 요청 '상하단을 최대한 여백 없이, 글자를 조금 줄여 쪽 수를 줄이기, 그림은 그대로'): 위 16·아래 10·좌우 15 mm 여백, 본문 9.2 pt, 장 제목 11 pt, 키워드 띠 13.5 pt, 날개 8 pt. 쪽 머리 글자와 쪽 번호는 종이 끝에서 5 mm 넘게 안쪽(프린터가 못 찍는 가장자리). III.03은 10쪽 → 8쪽.
  - 날개 없는 판(본문 180 mm, 그림 1.2배, 그림 하나뿐인 장은 카드 줄 옆에 그림)도 시험했으나 쪽 수가 같아(8쪽, 그림 1.1배로도 8쪽) 교사가 **날개 있는 판**을 고름(2026-11-05). 쪽 수를 더 줄이려면 그림을 줄이거나 내용을 빼야 함.
- **만드는 순서**
  1. 미리보기 서버 두 개를 켬: 저장소(8080, launch.json `slides`)와 학습지 폴더(8082, `worksheet`).
  2. 그림 목록 `figs.json`: 줄마다 `["저장 이름", 장 순번(0부터), 단계(99 = 마지막), "svg id"]`. svg id는 슬라이드 HTML의 장 안 그림(`.scn > svg`) id. 단계에 따라 그림이 바뀌는 장은 필요한 단계마다 한 줄씩(III.03 단열 변화: 3단계 = 올라갈 때, 마지막 = 내려올 때).
  3. 그림 꺼내기: `학습지_시험` 폴더에서 `node 도구/svgfigs.js 과목폴더/수업.html 수업폴더/figs.json 수업폴더/fig` — 헤드리스 크롬으로 슬라이드를 인쇄 모드(`?still=1&s=1&ans=0&print=1`)로 열어 SVG에 계산된 색·글꼴을 넣어 저장(III.03 그림 38개 약 0.8 MB). 끝에 `이름,이름`을 붙이면 그 그림만 다시.
  4. 원본 쓰기: 앞 수업의 `…_원본.html`을 복사해 내용만 바꿈. 장은 `<section class="blk"><div class="main">…</div><aside class="wing">…</aside></section>`, 빈칸 `[[번호:정답]]`, 그림 `<div class="fig" data-svg="이름" style="width:62mm" data-cap="그림 아래 이름표"></div>`. 카드 줄 문장은 슬라이드 그대로.
  5. `python build.py`(수업 폴더에서) → 완성본(그림을 파일 안에 넣음). 교사용은 완성본 주소 끝에 `?t=1`.
  6. PDF: `node 도구/printpdf.js 완성본주소 학생용.pdf 완성본주소?t=1 교사용.pdf`(크롬 인쇄 A4, 헤드리스 크롬 하나 — 남은 메모리 확인).
  7. 확인: 쪽마다 그림으로 바꿔 보고, PDF에서 ① 본문이 왼쪽 15 mm에서 시작하는지(쪽 전체가 줄어들지 않았는지) ② 날개 바탕(146.3~195 mm)에 걸치는 본문 글자·선이 없는지 ③ 쪽 아래 여백에 그려진 조각이 없는지 잼(pymupdf).
- **겪은 일**
  - 본문 칸(180 mm) 밖으로 나가는 요소가 하나라도 있으면 크롬이 쪽 전체를 줄여 인쇄함(92 %) → 본문이 날개 바탕을 침범하고 글자도 작아짐(1쪽 제목 덮개를 종이 폭으로 잡았다가 생김). 모든 요소를 본문 칸 안에.
  - 장 제목에 왼쪽 테두리(border)를 쓰면 쪽이 넘어갈 때 테두리 조각만 앞 쪽 끝에 남음 → `::before` 막대로.
  - 쪽 맨 위에서 시작하는 장은 위 여백이 사라져 쪽 머리 구분선에 붙음 → `@page` 위 여백 안에서 쪽 머리 칸에 `margin-bottom`을 줘 구분선을 본문보다 4 mm 위로 띄움(교사 지적).
  - 키워드 띠 꾸밈선을 끝까지 그으면 날개 바탕에 걸림 → 띠 폭을 본문 칸으로(교사 지적).
  - 그림 속 이름표를 정답이라고 가렸더니 범례·선 이름까지 사라져 그래프를 못 읽음(교사 지적) → 가리지 않음.
  - PDF 쪽을 잘라 SVG로 만들면 쪽 전체 내용이 남아 커짐(그림 30개 17 MB) → 슬라이드 화면에서 SVG를 직접 꺼냄.
  - 원본 HTML은 그림 자리만 있어 앱 파일 창 등에서 열면 그림이 안 보일 수 있음(교사 질문 '왜 그림이 하나도 없지?') → 보거나 인쇄는 완성본으로.

## 슬라이드 엔진 (모든 수업 슬라이드 공통)
**공용 엔진(`engine/deck.css`·`engine/deck.js`) + 수업마다 HTML 파일 하나**입니다(2026-11-05까지는 수업 파일마다 엔진이 통째로 들어 있는 단일 HTML). 외부 라이브러리 없음(글꼴 Pretendard만 jsDelivr CDN). III.03과 해일(II.04)은 수식용 KaTeX를 `<head>`에서 불러옵니다(엔진이 아닌 수업 전용, 아래 '만든 수업 기록').

파일 구조(위에서 아래로):
1. `<head>`: `<link rel="stylesheet" href="../engine/deck.css">`(엔진 CSS: 무대, 면 색, 글자 체계, 학습지·문제 부품, HUD, 목차, 레이저, 인쇄 모드) 다음 `<style>` — 그 수업 전용 스타일
2. `<div id="viewport"><div id="stage">` 안에 `<section class="slide">` 여러 장 — **수업마다 바뀌는 부분**
3. `<script src="../engine/deck.js"></script>` — 엔진(HUD·노트·도움말 마크업을 body에 넣고 `Deck`, `Ctx`, 등장 효과, 목차, 레이저, 책갈피, 키보드, 발표자 보기) — 수업 파일에서는 고치지 않음
4. 두 번째 `<script>` — `window.KW`, 정적 도형(계산해 그리는 그래프·화살표), `Deck.scene(...)` 장면들, 마지막 줄 `Deck.start()` — **수업마다 바뀌는 부분**

- 무대: 1920×1080 고정, `translate(-50%,-50%) scale(s)`로 화면에 맞춤. 모든 좌표는 무대 px.
- 슬라이드: `<section class="slide" id="s05" data-tile="dark|black|graphite|light|parchment" data-title="제목" data-notes="발표자 노트">`. `data-title`은 목차·노트에 쓰입니다. 그 장에만 쓰는 CSS는 section 안에 `<style>`을 넣고 `#s05 ...`처럼 범위를 한정합니다.
- 선언형 등장: `data-in="지연ms"`(장면 진입 시), `data-step="n"`(n번째 클릭), `data-fx="rise|fade|pop|left|up|scale|draw|wipe"`, `data-delay`, `data-dur`.
  - **주의:** `transform` 속성이 있는 SVG 요소에 `data-in`/`data-step`을 직접 달면 위치가 틀어집니다(CSS transform-origin). `<g data-step>`로 감싸고 transform은 안쪽 요소에 둡니다.
- 복잡한 움직임: `Deck.scene('s05',{steps, enter(c){}, go(c,k){}})`. 도구 `c.a / c.reveal / c.tween / c.count / c.loop / c.wait / c.$ / c.$$`. 장면을 떠나면 자동 정리.
  - 뒤로 가기·`&k=` 이동 시 원본 HTML 복원 후 순간 재생하므로, 상태는 `enter`/`go`에서 매번 다시 그리도록 작성(전역 상태 금지). 장면별 상태는 `c`(그 장의 Ctx)에 둡니다.
  - **계속 움직이며 단계마다 달라지는 장 패턴:** `enter`에서 처음 모습을 그리고, `go(c,k)`에서 `c.k=k`를 저장, 첫 `go`에서만 `c.lp=c.loop(...)`를 시작합니다. 루프는 매 프레임 `c.k`를 읽어 단계에 맞게 그립니다. 그리기 함수(예: `s05draw(c,t,k)`)는 두 번째 스크립트의 최상위 함수로 둡니다(검증 때 콘솔에서 직접 부를 수 있게). 조석 수업 5장·6장이 이 패턴의 예입니다.
  - 계산으로 만드는 고정 도형은 `Deck.start()` 전에 DOM에 넣으면 원본에 포함됩니다. 화살표는 `arrow(parent,x1,y1,x2,y2,color,width)`, 요소 생성은 `U.el(tag,attrs,parent)`.
  - 선을 그려 나가는 효과(`pathLength:1` + `stroke-dasharray:'1 1'` + `stroke-dashoffset`)는 offset 값을 소수 넷째 자리까지(`(1-e).toFixed(4)`) 넣습니다. 소수 첫째 자리로 반올림하는 `f1()`을 쓰면 10번에 나뉘어 끊겨 그려집니다(2026-11-02 교사 지적 '두두둑 끊기면서 그어짐').
  - `c.loop`는 `?still=1`에서도 계속 돕니다(계속 도는 장은 캡처 순간에 따라 모양이 달라짐).
- 애니메이션 중 클릭 = 그 애니메이션을 즉시 완료(다음 단계로 넘어가지 않음).
- 오른쪽 위 키워드: `window.KW={items:[...], at:[슬라이드별 키워드 번호 또는 -1]}` (`at` 길이 = 슬라이드 수). 목차 썸네일의 '번호 · 단원' 이름표도 여기서 가져옵니다.
- 화면 요소 위계: 머리(`.hd`: `.eb` + `h2`), 학습지 카드(`.ws-card` + `.ws-row`), 빈칸(`.bk` > `.a`(정답, data-step) + `.n`(번호)), 확인 문제(`.qz`), 정리 카드(`.rc`), 한 줄 요약(`.say-line`), 각주(`.fine`).
- 단축키: →/Space 다음, ← 이전, Shift+→/Shift+← 다음 장/이전 장(단계 건너뜀, 2026-11-03), N 노트(발표자 보기에서는 아래 칸의 단계 ↔ 노트 탭 전환), O 목차, P 일시정지, L 레이저 포인터, B/W 검은·흰 화면, F 전체 화면, M 책갈피, V 발표자 보기, ? 도움말, Esc 닫기(부분 확대 중이면 원래대로). 두 손가락 벌리기·트랙패드 핀치·Ctrl+휠 = 부분 확대.
- **장 단위 넘기기**(2026-10-29 교사 요청): 화면 누르기·방향키·밀기·발표자 보기의 [◀ 이전] [다음 ▶] 단추는 지금처럼 단계씩(`next`·`prev`). HUD의 ◀ ▶ 버튼, 마우스 휠, Shift+←/→(2026-11-03 교사 요청), 발표자 보기의 [이전 장] [다음 장] 단추는 남은 단계를 건너뛰고 장 단위로(`nextPage`·`prevPage`: 다음 장은 처음부터, 이전 장은 다 나온 상태로 — ← 키로 앞 장에 갈 때와 같음). 휠은 아래로 = 다음 장, 위로 = 이전 장. 트랙패드처럼 휠 신호가 길게 이어져도 한 번만 넘기고, 휠이 0.25초 멈춘 뒤에 다시 받음(`whNav`, 누적 30px 이상일 때 넘김). Ctrl+휠(확대)·확대 중 휠(옮기기)은 그대로이고, 옆으로 미는 휠·목차·그림 크게 보기·도움말·화면 끄기 중·노트/책갈피 창이나 스스로 스크롤되는 곳 위에서는 넘기지 않음. 발표자 보기에서는 지금 장 칸 위에서만. 검증: 헤드리스 Chrome에서 다섯 수업 모두 화면 클릭(단계)·▶·◀·휠 한 칸·빠른 두 칸(한 장)·0.5초 간격 두 칸(두 장)·트랙패드식 1초 연속(한 장)·옆 휠·Ctrl+휠·노트 위·목차 중·첫 장 위로·끝 장 아래로·→ 키를 확인.
- 발표자 노트(N, HUD 버튼): 화면 아래 패널. ✕ 버튼·Esc·N으로 닫힘. 열려 있으면 HUD가 노트 위로 올라가 가려지지 않습니다. 학생 모드에서는 숨김.
- 일시정지(P, HUD 버튼 ⏸): 그 장의 애니메이션(루프·tween·wait·WAAPI 등장 효과)을 모두 멈춥니다. 멈춘 동안 HUD가 계속 보이고 버튼이 파란 재생(▶) 모양으로 바뀝니다. 멈춘 상태에서 →·클릭·P를 누르면 그 자리부터 이어서 재생하고(다음 단계로 넘어가지 않음), 장·단계가 바뀌면 자동으로 풀립니다.
  - **수업에서 쓰는 법:** 계속 도는 그림(지구 자전, 조석 곡선 위의 점 등)을 설명하고 싶은 순간에 P를 눌러 세우고, 레이저(L)로 짚으며 설명한 뒤 →나 P로 이어 갑니다. 도움말(?)에도 적혀 있습니다.
  - **새 장면을 만들 때:** 시간은 직접 재지 말고 `c.loop`/`c.tween`/`c.wait`를 쓰면 일시정지가 저절로 적용됩니다. `setTimeout`·`setInterval`·`performance.now()`·`Date.now()`로 직접 만든 움직임은 멈추지 않습니다.
  - **실제 시계가 필요한 장(예: 모둠 활동 10분 타이머)**은 `performance.now()`를 쓰되, `html`의 `paused` 클래스를 `MutationObserver`로 지켜 멈춘 시간을 모아 빼 줍니다. 예: `과학탐구실험2/I.06environment.html`의 `s13` 장면(`off`에 멈춘 시간을 더하고 `performance.now()-t0-off`로 경과 시간 계산).
  - 엔진 구현: `engine/deck.js`의 `PAUSED`·`setPause()`. tween은 멈춘 시간만큼 시작 시각을 뒤로 밀고, loop는 멈춘 동안 시간을 더하지 않으며, `c.wait`는 tween으로 구현되어 함께 멈춥니다. 멈출 때 돌고 있던 WAAPI 애니메이션(HUD·노트·키워드 막대·목차 제외)은 `pause()` 했다가 `play()`합니다. `show()`(장 이동)와 `stepTo()`(단계 이동)에서 자동 해제, `next()`는 멈춰 있으면 해제만 하고 넘어가지 않습니다.
- 쪽 번호 + 단계 점(화면 아래 가운데, 늘 보임, 2026-10-23 교사 요청): 알약 모양 안에 '9 / 29'(지금 쪽 / 전체 쪽)와 그 장의 클릭 단계 점(지난 단계는 진하게)이 있습니다. 화면 맨 아래에 고정되어 16:9가 아닌 화면에서는 슬라이드 밖 검은 여백 위에 놓이므로 바탕을 깔아 밝은 장·어두운 장 모두에서 보이게 했습니다(교사 지적 '있다가 없다가 한다'). 폭 1440px 이하의 좁은 화면에서는 오른쪽 아래 도구 모음(HUD)이 가운데까지 와서 겹치므로, 도구 모음이 보이는 동안(마우스 움직임·일시정지) 그 위로 올라갑니다(교사 지적). 노트를 열면 노트 위로 올라갑니다.
- 레이저 포인터(L, HUD 버튼): 화면 위 투명 캔버스(`#laser`). 빨간 점이 마우스를 따라가고, 누른 채 움직이면 얇은 반투명 선(본선 2.5px, 투명도 `LZ_ALPHA=.7`)이 그려졌다가 떼면 1.1초 동안 사라집니다. 켜져 있는 동안 클릭은 슬라이드를 넘기지 않고, 터치로 좌우로 그어도 밀기(장 넘기기)로 보지 않으며(2026-10-23 교사 지적: 아이패드에서 레이저로 그으면 장이 넘어감 → 밀기 처리에서 레이저가 켜져 있으면 무시), 방향키로는 넘길 수 있으며 장·단계가 바뀌면 선을 지웁니다. Esc로 끄고, 목차를 열면 꺼집니다.
- 목차(O, HUD 격자 버튼): 실제 슬라이드가 작아져 격자로 펼쳐집니다(장 수에 맞춰 열 수 자동). 썸네일 아래 '번호 · 단원'과 `data-title`. 보던 장은 지금 상태 그대로, 나머지는 모든 단계가 나온 상태로 보입니다(계산으로 그리는 장면 내용은 그 장을 열기 전엔 비어 있을 수 있음). 누르거나 방향키+Enter로 고르면 그 장으로 확대되어 들어가 처음부터 재생, Esc·O는 보던 장으로 복귀.
- 주소 옵션: `?s=1` 학생 모드(노트 숨김), `?still=1` 정지 화면, `?ans=0` 빈칸 정답·문제 풀이·스스로 확인하기 예시 답안 숨김(학생용 인쇄), `?print=1` 레이저 인쇄용(모든 장을 흰 배경으로, 어두운 장의 밝은 글자·선은 어둡게), `?screen=1` 프로젝터 창(발표자 창을 따라감, 아래 '발표자 보기 + 프로젝터 창 연결'), `#3` 3번 장, `&k=2` 2단계(크게 쓰면 마지막 단계). 인쇄 모드에서 따로 손봐야 하는 장 전용 요소는 엔진 CSS의 `html.print ...` 규칙을 참고해 슬라이드 쪽 `<style>`에 추가합니다.
- 인쇄용 PDF(학생용만, 교사 요청 시): **벡터 PDF**로 만듭니다(2026-11-03 교사 '이미지가 거칠다, 벡터로 안 되나'). 쪽마다 헤드리스 Chrome(창 1920×1080)으로 `?still=1&s=1&ans=0&print=1&k=단계#N`을 열고 글꼴이 다 불린 뒤(`document.fonts.ready`) 크롬 인쇄 `Page.printToPDF`(종이 20 × 11.25 in = 1920 × 1080 CSS px, 여백 0, `printBackground`, `pageRanges:'1'`)로 한 쪽짜리 PDF를 만들고, 같은 출처 페이지(`localhost:8080`)에서 jsDelivr의 `pdf-lib@1.17.1`로 쪽들을 차례로 합칩니다(설치 없음). 글자·도형·수식이 벡터라 아무리 키워도 매끈하고, 흐림 효과(안개)만 그림으로 들어감(III.03 31쪽 6.8MB).
  - **'직접 해 보기' 장은 넣지 않습니다**(2026-11-03 교사: 교사가 직접 조작하지 않으면 의미가 없음). 제목(`data-title`)이 '직접 해 보기'로 시작하는 장을 빼고 만듭니다. III.03 학생용 PDF(31쪽)는 이 결정 전에 만들어 이 장들이 들어 있음(교사가 다시 만들 필요 없다고 함).
  - 화면을 찍어 넣는 방식은 쓰지 않습니다: 1920×1080은 레티나 화면·인쇄에서 흐리고('화질이 너무 엉망, 최소 Full HD급'), 4K(3840×2160)로 찍어도 확대하면 글자 가장자리가 계단처럼 보임.
  - **글자 둘레의 흰 띠**(`paint-order:stroke` + 흰 `stroke`, III.03의 `halo()`)는 학생용 인쇄에서 뺍니다(`html.print text[paint-order="stroke"]{stroke:none}`): 크롬 PDF 보기(PDFium)에서는 괜찮지만 pdf.js(파이어폭스·웹 PDF 보기)로 열면 띠가 글자색 덩어리로 그려짐. 다른 수업도 이런 띠를 쓰면 같은 규칙을 넣습니다.

## 다른 선생님께 드릴 단일 파일 (2026-11-05 교사 요청)
엔진을 떼어 낸 뒤로 수업 파일은 `engine` 폴더 없이는 열리지 않습니다. 다른 선생님께 드릴 때는 엔진과 그림을 수업 파일 안에 다시 넣어 **HTML 하나만으로 열리는 단일 파일**을 만듭니다(예전 방식과 같은 모양).
- 만드는 법: 저장소 폴더에서 `python engine/build_single.py 과목폴더/수업파일.html 출력경로.html`(출력 경로를 안 주면 지금 폴더에 `수업이름_단일파일.html`).
  - 하는 일: ① `<link … engine/deck.css>` 자리에 `<style>` + `deck.css` 내용, ② `<script src=… engine/deck.js>` 자리에 `<script>` + `deck.js` 내용(스크립트 안의 `</script` 글자는 `<\/script`로 바꿔 태그가 끊기지 않게), ③ '엔진을 못 찾으면 안내' 스크립트 빼기, ④ `img/…` 그림을 파일 안에 넣기(data URI), ⑤ 맨 위 안내 주석을 '단일 파일'로. 끝나면 크기·넣은 그림 수·아직 바깥 파일을 가리키는 곳을 알려 줌.
  - 스크립트를 못 쓰면 손으로: 위 ①·②·④를 그대로 하면 됨(엔진 두 파일의 내용을 그 자리에 붙여 넣고, 그림은 저장소의 `img` 폴더째 함께 드려도 됨).
- 만든 파일은 **저장소 밖**(교사가 정한 폴더)에 두고 커밋하지 않습니다.
- 그대로 인터넷이 필요한 것: 글꼴(Pretendard)과 수식(KaTeX)은 jsDelivr에서 불러옴 → 인터넷이 없으면 기본 글꼴, 수식은 대체 글로 보임.
- 확인: 만든 파일을 저장소가 아닌 다른 폴더에서 열어(파일 더블클릭 = file://) 장이 나오는지, 그림이 다 보이는지, '엔진 파일을 찾지 못했습니다'가 안 뜨는지, V(발표자 보기)가 되는지 봅니다. 2026-11-05 확인: 해일(2.6MB, 그림 8개)·III.03(0.4MB, 수식)을 저장소 밖에서 열어 엔진·그림·수식·발표자 보기 정상, 오류 0.
  - **2026-11-05 고침 — 파일로 연 단일 파일의 발표자 보기:** 위 확인은 V를 켜는 데까지만 봐서 놓쳤음. 단일 파일을 Chrome에서 직접 열고(file://) 장을 넘기면 미리보기 창의 `Deck`을 읽다 막혀(SecurityError) 지금 장이 비고 이전·다음 장 미리보기와 단계 칸이 멈췄음(교사가 Chrome에서 열어 보고 알림). 위 `pvCall`로 고친 뒤 여섯 수업을 사이트 방식(http)과 단일 파일(file://) 두 가지로 V → Shift+→로 모든 장을 넘기며 이전·다음 장과 단계 칸 iframe의 `Deck.i`·`Deck.k`를 확인(두 방식 모두 여섯 수업 130장, 오류 0, 예전 엔진은 같은 검사에서 어긋남이 잡힘), 프로젝터 창 연결도 두 방식 확인. 단일 파일을 확인할 때는 V를 켠 뒤 장을 몇 번 넘겨 봅니다.
